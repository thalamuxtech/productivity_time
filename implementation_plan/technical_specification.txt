1. EXECUTIVE SUMMARY
================================================================================

The Todo List Web App is a modern, highly interactive single-page application
designed to help users manage their tasks efficiently. The application focuses
on simplicity, beautiful UI/UX, and real-time features without requiring user
authentication.

KEY HIGHLIGHTS:
- Zero authentication friction (no login required)
- Real-time countdown for priority tasks
- Intelligent priority management (only one priority task allowed)
- Beautiful, responsive, and interactive UI
- Local-first approach with optional cloud sync
- Progressive Web App (PWA) capabilities

6. DATABASE SCHEMA
================================================================================

6.1 INDEXEDDB SCHEMA
--------------------

Database Name: TodoAppDB
Version: 1

OBJECT STORES:

Store 1: tasks
--------------
{
  id: string,                    // UUID v4
  title: string,                 // Task title (required, max 200 chars)
  description: string,           // Task description (optional, max 1000 chars)
  priority: 'priority' | 'high' | 'medium' | 'low',
  status: 'todo' | 'in-progress' | 'completed',
  deadline: number,              // Unix timestamp in milliseconds
  createdAt: number,             // Unix timestamp
  updatedAt: number,             // Unix timestamp
  completedAt: number | null,    // Unix timestamp or null
  tags: string[],                // Array of tag strings
  estimatedDuration: number,     // Minutes (optional)
  notes: string                  // Additional notes (optional)
}

Indexes:
- priority (for quick priority task lookup)
- status (for filtering)
- deadline (for sorting)
- createdAt (for sorting)

Store 2: settings
-----------------
{
  id: 'app-settings',
  theme: 'light' | 'dark' | 'system',
  sortBy: 'deadline' | 'priority' | 'createdAt',
  sortOrder: 'asc' | 'desc',
  defaultView: 'all' | 'active' | 'completed',
  notifications: boolean,
  soundEnabled: boolean
}

6.2 LOCALSTORAGE BACKUP
-----------------------
Key: 'todoapp_backup'
Structure: JSON stringified array of tasks
Purpose: Fallback if IndexedDB unavailable

6.3 DATA VALIDATION RULES
--------------------------
- Title: Required, 1-200 characters
- Priority: Only one task can have 'priority' status at a time
- Deadline: Must be future date for new tasks
- Status: Default is 'todo'
- Tags: Maximum 5 tags per task
- Description: Maximum 1000 characters

7. API DESIGN
================================================================================

Note: Since this is a client-side only app, this section describes the
internal data service layer (not HTTP APIs).

7.1 TASK SERVICE INTERFACE
---------------------------

class TaskService {

  // Create a new task
  async createTask(task: CreateTaskDTO): Promise<Task>

  // Get all tasks
  async getTasks(filter?: TaskFilter): Promise<Task[]>

  // Get task by ID
  async getTaskById(id: string): Promise<Task | null>

  // Get the current priority task
  async getPriorityTask(): Promise<Task | null>

  // Update task
  async updateTask(id: string, updates: Partial<Task>): Promise<Task>

  // Delete task
  async deleteTask(id: string): Promise<void>

  // Toggle task completion
  async toggleTaskStatus(id: string): Promise<Task>

  // Set task as priority (demotes current priority task)
  async setPriorityTask(id: string): Promise<Task>

  // Get task statistics
  async getTaskStats(): Promise<TaskStats>

  // Export tasks to JSON
  async exportTasks(): Promise<string>

  // Import tasks from JSON
  async importTasks(json: string): Promise<number>

  // Clear all completed tasks
  async clearCompleted(): Promise<number>
}

7.2 TYPE DEFINITIONS
--------------------

interface Task {
  id: string
  title: string
  description: string
  priority: PriorityLevel
  status: TaskStatus
  deadline: number
  createdAt: number
  updatedAt: number
  completedAt: number | null
  tags: string[]
  estimatedDuration: number
  notes: string
}

type PriorityLevel = 'priority' | 'high' | 'medium' | 'low'
type TaskStatus = 'todo' | 'in-progress' | 'completed'

interface CreateTaskDTO {
  title: string
  description?: string
  priority: PriorityLevel
  deadline: number
  tags?: string[]
  estimatedDuration?: number
  notes?: string
}

interface TaskFilter {
  status?: TaskStatus | TaskStatus[]
  priority?: PriorityLevel | PriorityLevel[]
  tags?: string[]
  searchTerm?: string
  deadlineBefore?: number
  deadlineAfter?: number
}

interface TaskStats {
  total: number
  completed: number
  active: number
  overdue: number
  completionRate: number
  averageCompletionTime: number
  tasksByPriority: Record<PriorityLevel, number>
}

9.2 PRIORITY TASK FEATURE
--------------------------

Business Rules:
- Only ONE task can be marked as 'priority' at any time
- Setting a new priority task automatically demotes the current one to 'high'
- Priority task must have a deadline
- Cannot mark completed task as priority

Visual Treatment:
- Featured card with gradient background
- Larger size than other tasks
- Animated border or glow effect
- Prominent position (top of dashboard)

Countdown Timer:
- Real-time countdown to deadline
- Format: "Xd Xh Xm Xs" or "Xh Xm Xs" if < 24 hours
- Color coding:
  * Green: > 24 hours remaining
  * Yellow: 6-24 hours remaining
  * Orange: 1-6 hours remaining
  * Red: < 1 hour or overdue
- Progress ring visualization
- Update every second
- Sound/notification when timer reaches zero (optional)

Implementation:
- Use setInterval or requestAnimationFrame for smooth updates
- Calculate remaining time in milliseconds
- Convert to human-readable format
- Update UI reactively

1. Title (required, text input)

- Position: Top-right or bottom-center
- Duration: 3-5 seconds

- Slide-in animation

- N: New task

- Esc: Close modal/dialog

- Space: Toggle completion (when task focused)
- E: Edit task (when task focused)

- S: Set as priority (when task focused)

Navigation:
- ↑/↓: Navigate tasks

12. PERFORMANCE CONSIDERATIONS
================================================================================

12.1 LOAD TIME OPTIMIZATION
---------------------------

Strategies:
1. Code Splitting
   - Split routes with React.lazy()
   - Lazy load modals and heavy components
   - Use dynamic imports for utilities
   - Target: Initial bundle < 200KB gzipped

2. Asset Optimization
   - Optimize images (WebP format)
   - Use SVG for icons
   - Minify CSS and JS
   - Enable compression (Brotli/Gzip)

3. Caching Strategy
   - Service Worker caching for static assets
   - Cache API responses
   - Long-term cache for immutable assets
   - Cache bust on updates

4. Font Loading
   - Use font-display: swap
   - Subset fonts to needed characters
   - Preload critical fonts
   - Consider system fonts for speed

Performance Targets:
- First Contentful Paint (FCP): < 1.5s
- Time to Interactive (TTI): < 3.5s
- Largest Contentful Paint (LCP): < 2.5s
- Cumulative Layout Shift (CLS): < 0.1

12.2 RUNTIME PERFORMANCE
------------------------

Strategies:
1. React Optimization
   - Use React.memo for expensive components
   - Implement useMemo for computed values
   - Use useCallback for function props
   - Avoid unnecessary re-renders
   - Profile with React DevTools

2. List Rendering
   - Implement virtual scrolling for large lists (react-window)
   - Use proper keys for list items
   - Paginate long lists
   - Render only visible items

3. State Management
   - Minimize global state
   - Use local state when possible
   - Avoid deeply nested state
   - Implement selector functions
   - Prevent unnecessary subscriptions

4. Animation Performance
   - Use transform and opacity for animations
   - Leverage GPU acceleration
   - Use will-change sparingly
   - Target 60fps for all animations
   - Use requestAnimationFrame

5. Timer Optimization
   - Use requestAnimationFrame for countdown
   - Throttle/debounce event handlers
   - Clean up intervals on unmount
   - Batch timer updates

Performance Monitoring:
- Use Chrome DevTools Performance tab
- Monitor with Lighthouse
- Set performance budgets
- Track Core Web Vitals

12.3 DATABASE PERFORMANCE
-------------------------

Strategies:
1. IndexedDB Optimization
   - Create proper indexes
   - Batch operations when possible
   - Use transactions efficiently
   - Implement pagination for large datasets
   - Clean up old data periodically

2. Query Optimization
   - Use indexed fields for filtering
   - Limit result sets
   - Implement cursor-based pagination
   - Cache frequently accessed data

3. Write Optimization
   - Batch write operations
   - Use optimistic updates
   - Implement write-back caching
   - Defer non-critical writes

12.4 MEMORY MANAGEMENT
----------------------

Strategies:
- Clean up event listeners
- Cancel pending requests on unmount
- Clear intervals and timeouts
- Avoid memory leaks in closures
- Monitor memory usage
- Implement lazy loading
- Use WeakMap for caches

Example Countdown Hook:
```typescript
function useCountdown(deadline: number) {
  const [timeRemaining, setTimeRemaining] = useState(0)

  useEffect(() => {
    const interval = setInterval(() => {
      const now = Date.now()
      const remaining = deadline - now
      setTimeRemaining(remaining > 0 ? remaining : 0)
    }, 1000)

    return () => clearInterval(interval)
  }, [deadline])

  return formatTime(timeRemaining)
}
```
